# 灵润可信调用扩展需求 v0.6

本轮在已运行的文字Demo基础上扩展协议、并发、流式交付、故障恢复和性能验证。适用范围继续为自定义提供商API Key模式，生产CA整合在灵润APK进程中。

## 责任范围

本项目接收灵润提供的请求体、提供商类型、HTTPS API前缀、模型参数及显式配置的Key，使用现有xkernel、GP和TEEC服务完成凭证管理与可信调用。CA、TA、必要SDK适配、通信链路、用户态部署与相关测试属于实施范围。

Framework/Binder、灵触的圈选/OCR和动作入口、提供商服务、设备固件与xkernel底层能力分别作为已存在的服务和输入使用。测试记录这些外部条件对结果的影响。模型内容质量、账号登录、供应商业务功能实现及xkernel底层安全性证明由相应组件负责。

## 功能与接口

| 项目 | 验收要求 |
| --- | --- |
| DeepSeek | 使用官方模型标识`deepseek-flash`，实际验证Chat Completions、Responses、Anthropic Messages的JSON与SSE |
| 灵润提供商 | 接受当前代码中的OpenAI-compatible、Responses、Messages、Gemini和Ollama Native配置，按类型派生API路径与鉴权 |
| 提供商配置 | HTTPS前缀与类型随凭证持久化，纳入CAS和receipt；请求固定其凭证版本及目的地快照 |
| 凭证恢复 | 保留现有DeepSeek凭证和旧snapshot，更新后的配置可查询，重启后引用继续可用 |
| 并发 | 当前目标4个活跃请求、8个GP会话；超限明确BUSY，各请求的响应、取消、期限和资源独立 |
| 流控 | CA增量交付HTTP头和body，慢消费者形成有界背压，调用失败、取消和关闭保持单一终态 |
| 原始数据 | 保留文字、工具字段、温度等浮点参数及图片data URI的原始JSON字节，TA校验上传长度和摘要 |
| 传输恢复 | 连接中断、进程退出、网络失败和可信VM停止产生明确失败，清理后可建立新请求，管理操作通过receipt对账 |
| 既有Demo | 关联MVP-01至MVP-08，保留文字动作、凭证引用、取消后恢复和持久化回归；新并发行为采用本轮协商上限 |

Ollama覆盖灵润现有云端HTTPS/API Key入口。其本地免Key服务属于另一个调用入口。文件上传等独立API端点按灵润实际调用需求另行评估。

## 性能与稳定性

| 项目 | 测量与判定 |
| --- | --- |
| 有效带宽 | 测量Java/CA经加密TEEC到TA的上传接管吞吐、消息粒度、调用次数及分位时延，包含多MiB负载 |
| 图片链路 | 使用确定性的合成图片，记录PNG和base64/JSON实际字节数，对同一Android、同一请求体做直接HTTPS与可信通路配对测量 |
| 等待时间 | 分别记录SDK初始化、上传、HTTP头、首个body和完整请求时间，并标注包含网络/提供商等待的指标 |
| 并发开销 | 比较单请求与4并发的吞吐、尾部时延、BUSY、取消影响和请求隔离 |
| 稳定性 | 连续至少20次Demo等价调用，额外多轮并发与故障后恢复，核对失败、资源回收和内存趋势 |
| 极端情况 | 覆盖容量边界、分片、零credit、慢消费者、callback错误/阻塞、期限耗尽、低内存和通信断开 |

性能报告给出安全通路相对基线的增量毫秒与比例、样本数和分位值。结合文字及图片Demo的实际体量判断可接受性，发现显著开销后继续定位和优化。配对测量使用短生命周期的独立测试程序，基线Key仅经stdin进入测试进程内存，记录结果均为非秘密计数。

## 验收边界

实际官方服务结果用于证明对应协议与凭证通路。Gemini及Ollama在缺少其官方服务凭证时，通过本地验证TLS peer覆盖路径、鉴权、编码和字节保真，并记录其服务端验收状态。宿主测试、实际TA、APK内模块和灵触联合演示分别保留证据。
