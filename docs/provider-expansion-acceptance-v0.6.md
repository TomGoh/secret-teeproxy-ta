# 协议、并发与通信性能验收矩阵 v0.6

每项记录源码/产物、设备boot、CID、请求体大小、运行命令、退出状态、断言和日志。失败尝试保留原记录，修正后的验证使用新日志。实际结果随本轮artifact报告更新。

## 通信和极端情况

| 测试 | 负载/故障 | 断言 |
| --- | --- | --- |
| 帧边界 | p1容量不足、最大合法帧、超长及损坏字段 | 拒绝无副作用，同seq合法容量重试，状态关联正确 |
| TCP分片 | 1、7、64、4096、16384字节接收片段 | TLS/HTTP/SSE跨片段保持字节与终态正确 |
| 流控 | 零credit、小credit、慢listener | 缓冲有界、无丢字节、ACK产生背压 |
| callback故障 | 抛异常、取消时callback尚未返回、超过期限 | 单一结果、禁止后续事件准入、SDK保留清理责任 |
| 内存边界 | 最大body预留、总量64MiB、clone OOM、输出超限 | 明确拒绝、释放预留、下一请求可用 |
| 通信丢失 | 上传中和TLS中终止CA进程、网络错误、截断响应 | 正确失败，slot回收，新连接与新请求恢复 |
| 凭证竞争 | 并发请求期间PUT和DELETE | PUT保留旧请求快照，DELETE撤销所有版本的在途快照 |
| 兼容和带宽 | 初始16KiB HELLO、旧CA、新CA与bulk能力协商 | 旧端点15000 B、新端点57280 B切片，偏移、digest与响应关联全部正确 |
| 序列化容量 | 61440 B输入、32768 B输出、p0输入清理 | 请求61478 B、回复32798 B，旧回显越界样例被明确检测 |
| SDK地址校验 | 跨相邻RW/R映射的合法输入及写入只读区 | 连续可读输入成功，缺页和权限不足的访问被拒绝 |
| 实例空闲回收 | 超过2048映射后关闭全部会话、并发新Open | 真实Child退出后新实例启动，pending Open持有准入保护，同context关联一致 |
| 应用数据持久化 | APK正常更新、runtime重启、TA空闲回收、同volume VM重启 | protection设置、凭证ref/version、绑定配置和删除后的Android旧Key属性计数一致 |
| 长期稳定 | 多轮单路/并发/故障交替 | 成败计数完整、无累积的活跃slot或持续增长的内存趋势 |

## 性能

| 测量 | 组合 | 输出 |
| --- | --- | --- |
| TEEC上传 | 0、16KiB、256KiB、1、4、8MiB；1/4 worker；多种chunk | 接管吞吐MiB/s、Invoke次数、p50/p95/p99/max |
| 增量响应 | 不同body体量、正常/慢消费者 | 首HEAD/首BODY/总时间、body字节、峰值排队、取消观察时间 |
| 图片配对 | 同Android、同PNG/JSON；直接HTTPS与可信通路交替 | 上传、首body、完整时间、增量毫秒与比例 |
| 文字配对 | 相同文本和预算，多轮交替 | provider等待波动、SDK/TA开销分布 |
| 并发 | 1/4请求，固定payload和credit | 吞吐扩展、尾延迟、超限拒绝和故障隔离 |

直接基线采用独立测试程序，Key仅通过stdin进入短生命周期进程。性能样本包括预热和多轮交替，记录每轮成功或失败。远端模型时间包含在端到端指标中，通信吞吐和Invoke指标单独呈现。

验收报告给出实际可接受的Demo体量和明显开销的来源。Gemini/Ollama官方服务、物理掉电、xkernel安全证明及上层OCR质量分别标明所属组件和当前证据状态。
